# Что собеседник может сделать с чатами пользователя

[← к оглавлению](../README.md)

**Состояние:** закрыто 2026-11-26 (ветка `canonical-address`). Поводом стал внешний отчёт о
подделке фантомов синхронизации; после него проверены остальные пути, по которым письмо от
собеседника меняет данные пользователя.
**Тесты:** `pnpm test:sync-sender`, `pnpm test:peer-authority`.

## Модель угрозы

Отправителя письма ASMail удостоверяет платформа (`msg.sender`). Всё остальное в JSON-теле
письма пишет сам отправитель. Атакующий — любой, чьё письмо пропустит inbox: собеседник,
участник группы или незнакомец, приславший приглашение. Обработчик не должен верить телу
ни в чём, что отправитель не вправе решать сам.

Общие проверки формы тела вынесены в
`src-deno/services/chat-service/utils/peer-input-checks.ts`.

## Правила, которые теперь соблюдаются

| Что | Правило | Где |
|---|---|---|
| Фантом синхронизации | только от собственного адреса | `incoming-messages.ts` |
| Удаление «у всех» | в личном чате — любое обычное сообщение; в группе — автор или админ; системные записи не удаляются | `msg-deletion.ts` (`mayPeerDelete`), UI: `delete-for-everyone.ts` |
| Правка сообщения | только автор, только обычные сообщения, тело — строка | `msg-editing.ts` |
| Реакции | отправитель меняет только свою реакцию | `msg-reactions.ts` |
| Настройки чата | только известный период автоудаления; прочие поля не берутся | `chat-setting-up.ts`, `autoDeleteOptionIdOf` |
| Принятие личного чата | только если приглашение отправлял пользователь (`initiated`) | `chat-creation.ts` |
| Принятие группового | только от того, кто уже есть в `members` | `chat-creation.ts` |
| Список принявших от админа | не ставит пользователю `hasAccepted` и статус `on` | `chat-creation.ts` |
| Групповое приглашение | участники и админы — адреса без дубликатов, админы среди участников | `checkedGroupInvitation` |
| Состав и админы группы | структура проверяется, админ — только участник | `chat-members-updating.ts` |
| Имя чата | строка, одна строка, не длиннее 200 символов; в HTML — экранируется | `normalizeChatName`, `escape-html.ts` |
| Системное событие с записью | без `chatMessageId` не применяется | `incoming-system-msgs.ts` |
| Превью записи | только inline-картинка `data:image/…`, только для реальных вложений | `checkedRecordings` |
| Звонок | не звонит в чате, который пользователь не принял; `hostAddr` — участник или сам собеседник | `incoming-signals.ts` |
| Подделанные ссылки и упоминания | если текст не совпадает с адресом, сначала спросить пользователя | `useChatMessages.ts` |
| Исполняемые вложения | перед открытием спросить пользователя | `risky-file.ts`, `useOpenAttachment.ts` |
| Бэкап | записи чатов проверяются как приглашения; PBKDF2 не больше 10 млн итераций | `chat-backup-srv.ts`, `backup-crypto.ts` |
| Тестовый хук `handleIncomingMsg` | в IPC только на тест-стенде | `ipc-expose.ts` |

## Остаточные риски

- **Id группы можно занять первым.** Участник группы, знающий её id, может прислать
  поддельное приглашение раньше настоящего. Настоящее тогда отбрасывается как «чат уже
  есть». Общего доверенного источника состава группы у приложения нет.
- **«Переслано от» — слово пересылающего.** Пересылку проверить нельзя по самой её
  природе. Проверяется только, что это адрес.
- **Столкновение звонков.** Если пользователь сам звонит в чат, а собеседник одновременно
  тоже звонит и называет свой звонок установленным, пользователь присоединится к звонку
  собеседника. Это то, как разрешается встречный звонок, а не навязанный звонок. Данные
  `established/startedAt` проверить нельзя.
- **Потерянное устройство пользователя** закрыть средствами приложения нельзя: см.
  предложение платформе `platform-issues/platform-proposal-device-keys-2026-11-26.md`.
