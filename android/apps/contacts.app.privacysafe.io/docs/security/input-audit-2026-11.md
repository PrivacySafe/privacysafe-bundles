# Что другие приложения, файлы и устройства могут сделать с адресной книгой

**Статус:** закрыто 2026-11-26. Поводом стал отчёт о подделке синхронизационных
фантомов в чате. Здесь такой уязвимости нет: синхронизация идёт через synced FS
платформы (файл SQLite и папка изображений), фантомов нет. Аудит проверил
другие пути, по которым чужие данные попадают в адресную книгу.
**Тесты:** `tests/unit/src-deno/utils/contact-input-checks.spec.ts`,
`tests/unit/src/common/composables/use-contacts-import.spec.ts`,
`tests/unit/src/common/utils/css-image-url.spec.ts` и дополнения в спеках
архива, бэкапа, слияния, адресов и стартовых команд.

## Откуда приходят чужие данные

- **Другие приложения** через сервис `AppContacts` и стартовую команду
  `add-contact`.
- **Другой пользователь**, приславший файл с контактами (`.w3nec`).
- **Файл бэкапа**, который пользователь восстанавливает.
- **Свои же устройства**: файл БД и аватары в synced FS. Здесь речь об
  устойчивости, а не об атаке.

## Правила

| Что | Правило | Где |
|---|---|---|
| Диалоги подтверждения | HTML санитизируется, подставляемые значения экранируются. Имя контакта в диалогах удаления и блокировки, а также версия бэкапа (показывалась ещё до согласия на восстановление) выполнялись как HTML | `confirmation-dialog.vue`, `use-contact.ts`, `use-backup-restore.ts` |
| Сервис `AppContacts` | открыт только Chat и Inbox. Раньше любое установленное приложение могло молча прочитать всю книгу, переписать любой контакт и снять блокировку | `manifest.json` |
| Запись контакта | адрес проверяется как адрес, текстовые поля — строки ограниченной длины (имя — одна строка), id аватара без пути, `settings`/`activities` своей формы. Обновление без `settings` сохраняет прежние, а не снимает блокировку | `src-deno/utils/contact-input-checks.ts`, `contacts-deno-srv.ts` |
| Команда `add-contact` | берутся только адрес и имя. `id` из аргумента превращал форму «нового» контакта в правку существующего | `use-command-handler.ts` |
| Адрес | строгая проверка: есть `@`, непустое имя пользователя, домен валиден, в том числе IDN. Раньше `"x"` превращался в `"@x"` | `shared-libs/address-utils.ts` |
| Импорт присланных контактов | новые контакты добавляются только после подтверждения со списком «имя — адрес». Не больше 5000 контактов, поля ограничены, аватары только растровые (без SVG) | `use-contacts-import.ts`, `import-contacts-dialog.vue`, `shared-contacts-archive.ts` |
| Подготовка импорта для другого приложения | файл не больше 64 МБ, не больше 5 ожидающих импортов | `contacts-import-srv.ts` |
| Шеринг | заметки о контакте (`notice`) больше не отправляются | `contacts-share-srv.ts` |
| Бэкап | строки контактов проверяются (адрес, текст, id аватара); аватары только как data URL растровых изображений; PBKDF2 не больше 10 млн итераций | `backup-archive.ts`, `contacts-backup-srv.ts`, `backup-crypto.ts` |
| Текстовые колонки при чтении | число или blob в `name`/`notice`/`phone` читается как строка. Раньше такая строка роняла список контактов на всех устройствах | `contact-row-mapping.ts`, `contacts-db.ts` |
| Аватар в CSS | только `url("…")` в кавычках и только для `data:image/…` или `blob:` | `css-image-url.ts` |
| Файл БД с другого устройства | отсутствующая или пустая таблица не вызывает исключения; строки без адреса пропускаются, перезапись таблицы не обрывается на середине; слияние сравнивает адреса в канонической форме | `contacts-db.ts`, `handle-db-file-sync-status.ts`, `resolve-root-folder-conflict.ts`, `db-file-conflict.ts` |
| Уведомления о датах | имя в уведомлении — одна строка, не длиннее 80 символов | `reminder-notifications.ts` |

## Что не меняли

- **`add-contact` по-прежнему открыт всем приложениям.** Ссылки
  `w3n://add-contact` нужны и после аудита. Теперь команда только
  предзаполняет форму нового контакта адресом и именем.
- **Чтение аватара по `avatarId` внутри папки изображений.** Как платформа
  ограничивает пути, видно только из её кода. После аудита `avatarId` без
  пути, а внешних вызывающих осталось двое: Chat и Inbox.
